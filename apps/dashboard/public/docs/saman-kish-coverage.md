# سامان کیش (سپ) — وضعیت پوشش آداپتور

این آداپتور **آزمایشی** است: جریان پایه اجرا می‌شود، اما همه‌ی مسیرهای درگاه پوشش داده
نشده است. این سند عمداً کوتاه است و فقط چیزی را توصیف می‌کند که واقعاً پیاده شده.

## وضعیت

| قابلیت | وضعیت |
|---|---|
| توکن‌سازی | پیاده‌سازی شده |
| خرید مستقیم (direct pay) | پیاده‌سازی شده |
| وریفای دو مرحله‌ای | **در حال تکمیل** |
| خطاهای شبکه‌ی شاپرک | **پوشش ناقص** |
| بازپرداخت | پیاده‌سازی شده |

## مسیر

```
http://localhost:8080/saman-kish
```

در محیط عملیاتی، دامنه و مسیر را با مستندات رسمی سرویس تطبیق دهید؛ این آداپتور
مستند رسمی کاملی برای تطبیق خودکار ندارد.

## جریان تست

```
POST /saman-kish/payment
X-IPG-Scenario: approve | decline | timeout | pending_settle | verify_failed | refund
```

پس از پرداخت موفق، پاسخ شامل `token` است. همان توکن را در مرحله‌ی بعد (وریفای یا
پرداخت مستقیم) بفرستید. پاسخ نهایی شامل `status` و `track_id` خواهد بود.

## سناریوها

| سناریو | وضعیت پشتیبانی |
|---|---|
| `approve` | پشتیبانی می‌شود |
| `decline` | پشتیبانی می‌شود |
| `timeout` | پشتیبانی می‌شود |
| `pending_settle` | پشتیبانی می‌شود |
| `verify_failed` | پشتیبانی می‌شود |
| `refund` | پشتیبانی می‌شود |
| خطاهای شبکه‌ی شاپرک | **پوشش ناقص** |

## نمونه‌ی cURL

```bash
curl -X POST http://localhost:8080/saman-kish/payment \
  -H "Content-Type: application/json" \
  -H "X-IPG-Scenario: approve" \
  -d '{
    "order_id": "9042",
    "amount": 2500000,
    "callback": "http://localhost:3000/verify"
  }'
```

## چرا هنوز آزمایشی است

وریفای دو مرحله‌ای در درگاه واقعی دو پیام مجزا با دو شناسه دارد و بازپرداخت آن هم از
مسیر متفاوتی انجام می‌شود. تا وقتی هر دو مسیر بازتولید شوند، روی این آداپتور تست
پولی واقعی انجام ندهید.

---
این سند وضعیت پیاده‌سازی سندباکس را توصیف می‌کند، نه قرارداد رسمی درگاه.
