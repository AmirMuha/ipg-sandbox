# آیدی‌پی (IDPay) — مرجع API نسخه ۱.۱

مرجع کاری برای آداپتور آیدی‌پی در سندباکس درگاه. دامنه را به لوکال تغییر دهید و همان
هدرها را بفرستید.

- مسیر پایه در سندباکس: `http://localhost:8080/idpay/v1.1`
- مسیر پایه در درگاه واقعی: `https://api.idpay.ir/v1.1`
- احراز هویت: هدر `X-API-KEY` روی همه‌ی متدها

## ۱. ساخت پرداخت

```
POST /v1.1/payment
X-API-KEY: <کلید پذیرنده>
Content-Type: application/json
```

بدنه‌ی درخواست:

| فیلد | نوع | توضیح |
|---|---|---|
| `order_id` | عدد یا متن | شناسه‌ی سفارش شما |
| `amount` | عدد | مبلغ به **ریال** |
| `callback` | آدرس | آدرس بازگشت |
| `customer_phone` | متن | اختیاری |
| `customer_mail` | متن | اختیاری |

پاسخ:

```json
{ "id": "1234567", "link": "https://idpay.ir/payment/1234567" }
```

کاربر را به `link` بفرستید؛ در سندباکس این همان صفحه‌ی پرداخت میزبان است.

## ۲. استعلام وضعیت

```
GET /v1.1/payment/{id}/status
```

```json
{
  "id": "1234567",
  "status": "PAID",
  "track_id": 987654321,
  "amount": 2500000,
  "order_id": "9042",
  "date": "1700000000"
}
```

`status` مهم‌ترین فیلد است: `PAID` یعنی پرداخت کامل شده، `FAILED` یعنی ناموفق.

## ۳. تایید (Verify) — اختیاری

```
POST /v1.1/payment/verify
X-API-KEY: <کلید پذیرنده>
```

بدنه: `{ "id": "1234567", "order_id": "9042" }`

تایید را **یک‌بار** صدا بزنید. اگر پاسخ `101` گرفتید، تراکنش قبلاً تایید شده و تکرار
تایید خطا می‌دهد.

## ۴. کدهای خطای متداول

| کد | معنی |
|---|---|
| `10` / `11` | پذیرنده نامعتبر است یا دسترسی ندارد |
| `12` | مبلغ نامعتبر است |
| `30` | پرداخت یافت نشد |
| `31` | کارت بانکی نامعتبر است |
| `33` | مبلغ تراکنش با مبلغ تاییدشده یکی نیست |
| `34` | سقف تقسیم تراکنش‌ها تکمیل شده است |
| `40` | پارامترهای ارسالی نامعتبر است |
| `101` | تراکنش قبلاً تایید شده است |
| `102` | تراکنش تاییدنشده است |

## ۵. سناریوهای سندباکس

```
X-IPG-Scenario: approve | decline | timeout | pending_settle | verify_failed | refund
```

| سناریو | نتیجه‌ی قابل انتظار |
|---|---|
| `approve` | `status: PAID` و `track_id` برگشتی |
| `decline` | `status: FAILED` |
| `timeout` | پاسخ HTTP `504` |
| `pending_settle` | `status: CREATED` و سپس `PAID` |
| `verify_failed` | تایید خطا می‌دهد، حتی با پرداخت موفق |
| `refund` | تراکنش بازپرداخت می‌شود |

## ۶. نمونه‌ی cURL

```bash
curl -X POST http://localhost:8080/idpay/v1.1/payment \
  -H "Content-Type: application/json" \
  -H "X-API-KEY: sandbox-idpay-test-key-9941" \
  -H "X-IPG-Scenario: approve" \
  -d '{
    "order_id": "9042",
    "amount": 2500000,
    "callback": "http://localhost:3000/verify"
  }'
```

این سند جریان و شکل پیام‌ها را مطابق قرارداد رایج درگاه و پیاده‌سازی سندباکس توصیف می‌کند.
پیش از رفتن به محیط عملیاتی، مقادیر را با مستندات رسمی به‌روز درگاه تطبیق دهید.
