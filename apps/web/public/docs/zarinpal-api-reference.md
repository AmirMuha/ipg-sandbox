# زرین‌پال — مرجع API (نسخه ۴ REST)

مرجع کاری برای آداپتور زرین‌پال در سندباکس درگاه. برای تست، فقط `localhost:8080` را جای دامنه‌ی
درگاه بگذارید؛ بقیه‌ی قرارداد دست‌نخورده می‌ماند.

- مسیر پایه در سندباکس: `http://localhost:8080/zarinpal/pg/v4`
- مسیر پایه در درگاه واقعی: `https://api.zarinpal.com/pg/v4`
- محتوا: `application/json`

## ۱. درخواست پرداخت

```
POST /pg/v4/payment/request.json
```

بدنه‌ی درخواست:

| فیلد | نوع | توضیح |
|---|---|---|
| `merchant_id` | uuid | شناسه‌ی پذیرنده (در سندباکس: `00000000-0000-0000-0000-000000000000`) |
| `amount` | عدد | مبلغ به **ریال** |
| `description` | متن | شرح سفارش |
| `callback_url` | آدرس | آدرس بازگشت کاربر |
| `metadata` | object | اختیاری — داده‌ی دلخواه |
| `mobile` | متن | اختیاری — شماره‌ی کاربر |

پاسخ موفق:

```json
{
  "data": {
    "code": 100,
    "message": "Success",
    "authority": "A0000000000000000000000000000000000001",
    "fee_type": "IN",
    "fee_amount": 0
  },
  "errors": []
}
```

کاربر را به `data.code == 100` یعنی به آدرس `https://www.zarinpal.com/pg/StartPay/<authority>`
بفرستید (در سندباکس همان صفحه‌ی پرداخت میزبان شبیه‌سازی‌شده است).

## ۲. تایید تراکنش

```
POST /pg/v4/payment/verify.json
```

بدنه: `merchant_id`، `amount`، `authority`.

| `data.code` | معنی | رفتار اپلیکیشن |
|---|---|---|
| `100` | تایید و تسویه موفق | سفارش را نهایی کنید |
| `101` | این تراکنش قبلاً تایید شده | موفق در نظر بگیرید، دوباره تسویه نکنید |
| `102` | تایید با این مبلغ ممکن نیست | به کاربر خطا بدهید |
| `103` | تراکنش تاییدنشده و منقضی شده | اجازه‌ی پرداخت دوباره بدهید |

## ۳. کدهای خطای متداول

| کد | معنی |
|---|---|
| `-50` | پذیرنده یا پارامترها نامعتبر است |
| `-51` | پرداخت ناموفق |
| `-33` | مبلغ تراکنش نامعتبر است |
| `-30` | اجازه‌ی استفاده از این متد را ندارید |
| `-40` | دسترسی به سرویس مجاز نیست |

## ۴. تسهیم و استعلام

- تسهیم: همان جریان `verify` با `settle` روی تراکنش‌های تاییدشده.
- استعلام وضعیت یک `authority` از طریق داشبورد سندباکس (ستون **Scenario** در جدول تراکنش‌ها).

## ۵. سناریوهای سندباکس

هر سناریو را با هدر زیر روی هر درخواستی بفرستید تا همان نتیجه در تست شما تکرار شود:

```
X-IPG-Scenario: approve | decline | timeout | pending_settle | verify_failed | refund
```

| سناریو | نتیجه‌ی قابل انتظار |
|---|---|
| `approve` | `verify` با `code: 100` |
| `decline` | `code: 101` بعد از بازگشت کاربر |
| `timeout` | پاسخ HTTP `504` |
| `pending_settle` | ابتدا `pending`، پس از ۵ ثانیه تایید می‌شود |
| `verify_failed` | پرداخت در درگاه موفق، `verify` خطا می‌دهد |
| `refund` | تراکنش به وضعیت `refunded` می‌رود |

## ۶. نمونه‌ی cURL

```bash
curl -X POST http://localhost:8080/zarinpal/pg/v4/payment/request.json \
  -H "Content-Type: application/json" \
  -H "X-IPG-Scenario: approve" \
  -d '{
    "merchant_id": "00000000-0000-0000-0000-000000000000",
    "amount": 2500000,
    "description": "Order #9042",
    "callback_url": "http://localhost:3000/verify"
  }'
```

---
این سند جریان و شکل پیام‌ها را مطابق قرارداد رایج درگاه و پیاده‌سازی سندباکس توصیف می‌کند.
پیش از رفتن به محیط عملیاتی، مقادیر را با مستندات رسمی به‌روز درگاه تطبیق دهید.
