# Data Model: Client Payment Journeys E2E Testing

## Test Entities & Lifecycle

### 1. Test Merchant (`Merchant`)
The simulated client persona driving the test interactions.

**Attributes**:
- `email` (string): Unique email per run (`e2e-${timestamp}@example.com`).
- `password` (string): Standard test password meeting strength requirements (`Password123!`).
- `fullName` (string): Display name (`E2E Merchant`).

**Lifecycle**:
- Created during setup via `POST /api/v1/auth/register`.
- Used to authenticate via UI login form at `/en/login`.

---

### 2. Client Payment Simulation (`Transaction`)
The payment transaction initiated by the client and walked through checkout.

**Attributes**:
- `id` (UUID): Unique transaction identifier generated by the engine.
- `authority` (string): Emulated gateway authority reference (e.g., `A...` for Zarinpal).
- `amount_rial` (integer): Canonical amount in Iranian Rials (e.g., `1,500,000`).
- `app_reference` (string, optional): Client's internal order reference (e.g., `ORDER-1001`).
- `status` (string): State machine progression (`initiated` -> `pending` -> `settled` or `declined`).
- `checkout_url` (string): URL to the emulated gateway hosted payment page.

**State Transitions Tested**:
1. **Approval Path**: `initiated` -> `pending` (via hosted checkout confirm) -> `settled` (via backend verification).
2. **Decline Path**: `initiated` -> `declined` (via hosted checkout fail/cancel).

---

### 3. API Key Token (`ApiKey`)
Programmatic credential provisioned for server-side API calls.

**Attributes**:
- `name` (string): Label provided by client (e.g., `Production app`).
- `token` (string): Plaintext secret starting with `ipg_key_`, exposed only once upon creation.
- `last_four` (string): Last 4 characters stored and displayed in UI table for identification.
- `revoked_at` (timestamp, nullable): Set when revoked.

**State Transitions Tested**:
- **Active**: Created in modal -> valid for `Bearer` authentication against `/api/v1/auth/me`.
- **Revoked**: Revoked via table action -> permanently rejected with HTTP 401.

---

### 4. Webhook Delivery Event (`WebhookDelivery`)
Asynchronous event emitted by the sandbox engine upon transaction settlement.

**Attributes**:
- `target_url` (string): Destination endpoint (`http://127.0.0.1:3099/callback`).
- `stage` (string): Event stage (`settle` / `payment.approved`).
- `attempt` (integer): Delivery attempt number (1..retry_max).
- `result` (string): Delivery status (`delivered` or `failed`).
- `response_status` (integer): HTTP status code returned by callback server (e.g., `200`).
- `payload` (JSON): Wire payload delivered to the client endpoint.
